# 参考网页重设计指南

本文件适用于 `demos/` 中的页面与配套样式。目标是重设计集群构建时使用的**参考网页**；页面视觉、文案、布局和组件形式可以大胆改变。不要把当前配色、卡片形状或版式当成必须保留的规范。

## 页面范围与职责

- 小红书离线版收录 `home.html`、`console.html`、`blender.html`，案例键为 `home`、`console`、`blender`（见 `minitool/vite.config.ts` 的 `CASE_KEYS`）。保留三种不同的演示场景：产品首页、信息密集的控制台、Blender 工作区。`tests/fixtures/tall.html` 保留为本地滚动与镜头跟随测试夹具。其余 `demos/*.html` 是本地演示或试验页，不会自动进入小红书包。
- 三页的可构建主体保留在 `#app` 中；保留 `body` 上对应的 `data-demo`，以及各页根类。它们被页面挂载、样式、翻译或演示逻辑引用。修改这些接口前，先同步检查 `demos/creator.ts`、`demos/lang.ts`、`demos/shell-core.ts` 和 `minitool/src/shell.ts`。
- 首页是 Swarm Builder 的产品介绍。功能、参数、版本和安装方式等事实以仓库源码、`package.json`、`README.md` 为准；不要把尚未发布的 npm/CDN 或未实现的功能写成已上线。控制台可以使用虚构数据，但应清楚地呈现为演示内容。
- 三页应提供丰富且各不相同的可见 DOM 内容，供光标采集、排工和构建。本地测试用长页面必须有真实的纵向滚动空间，以展示镜头跟随；不要用一张整页图片代替 DOM 页面。

## 小红书容器边界

- `minitool/vite.config.ts` 会读取上述三页 HTML，移除其中的 `<script>` 和 `<link>`，再将页面挂入 `[data-viewport]` 的 Shadow Root。关键内容必须直接存在于 HTML 中；关键样式放在 `demos/demo.css`、`demos/console.css` 或页面内 `<style>`，不要依赖页面脚本、远程 CSS、在线字体、远程图片或接口才能显示。
- 不在案例内容中使用 `iframe`、`object`、行内事件处理器或 `target` 跳转。小红书版离线运行，站外导航和联网抓取不属于这些参考页的能力。外链可作为文本/视觉信息，但不能成为完成体验的必经步骤。
- 兼顾 Chrome 61 / ES2017 基线。避免只靠较新的 CSS 特性完成核心布局；构建期的 `minitool/build/cssfix.ts` 与产物门禁会检查兼容性。新增媒体资源须能离线打包，并核对最终包内的相对路径。
- 外壳负责进场 Logo、光标汇聚、构建、顶栏展开和创造者悬浮球。页面重设计不要复制这些外壳功能，也不要把面板设为默认展开。页面应让真实 DOM 在构建结束后正常显示并可交互。

## 布局与交付检查

- 检查桌面和手机窄屏：文字可读、主要操作可见、页面宽度不超过视口；长页面在容器自己的滚动区域内滚动，外壳文档不应被页面撑高。
- 页面里的交互控件用合适的语义元素，链接与按钮要有可辨识的文字或标签。交互若需脚本，小红书版须在共享挂载逻辑中实现，而不是只写在页面 `<script>` 中。
- 改动完成后至少运行 `npm run typecheck`、`npx vite build --config minitool/vite.config.ts`，并在本地案例浏览器检查三页的构建过程与完成态。涉及小红书交付时，再运行仓库的容器冒烟检查；通过桌面浏览器不等于通过容器。
- 多个 agents 同时设计时，按页面分工并先约定共享 CSS 的编辑归属；不要互相覆盖 `demo.css` / `console.css`。提交说明写明改了哪几页、实际检查了哪些视口和运行环境。
