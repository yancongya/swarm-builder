它拆出什么，就盖回什么

矩形与骨架

盒子带着尺寸徽章落位，边框、圆角、底色照采集那一帧还原；容器先把骨架撑起来。

逐字打字

文本一个字符一个字符敲出来，I 型光标与插入符跟着走；大标题能边打字边长到真实字号。

媒体与降级

img、svg、canvas/video 截帧都会真的呈现；取不到的资源降级成占位框，不会留一个洞。

重复模块盖章

一列相似的兄弟只真做一个，其余按住 ⌥ 拖过去盖章，卡片墙不必一行行重打。

辅助线与吸附

布局本来就有的对齐线先画出来，盒子落位时吸上去，收尾再淡出。

多光标集群

1–24 个光标同场施工，认领顺序七套可选；开工时按预估工时均衡，大家差不多同时收工。

和扩展版哪里不一样

效果基准是 Chrome 扩展「Swarm Rebuild」：它装在浏览器里，你打开哪一页就盖哪一页；这一份装在页面里，只有访问你站点的人看到。下面每一条优缺点都是从这一句区别里长出来的。

维度扩展版本库
装在哪儿浏览器里，只对你这台机器生效页面里，每个访问者都拿到
能盖谁当下打开的任何网站你自己部署的那一棵 root 子树
改参数扩展弹窗里点18 项配置、控制方法、完成回调，类型全在
第二遍每次进来都是新的一局seed 固定就逐帧一致，同一场施工可重放
能不能自动化得人对着浏览器点headless 里跑完直接读结果
带多少东西一个扩展gzip 15 KB 的核心包，零依赖，ESM / CJS / IIFE 随取
许可无明确授权，源码不可复用MIT

库这头多出来的

  • 定速进场：给一个秒数，倍率交给估算器反推，整场压到那一秒收尾。
  • 七套认领顺序加等工时切带：谁守哪条带、谁先盖由你选，扩展是固定顺序。
  • 它成了你页面的一部分：可以只盖首屏、可以只挂一个子树、可以把真实 DOM 原样交还。
  • 调好就导出：创造者模式一键把这一局参数变成可粘贴代码，也能整段交给 agent。
  • 有降级路径：跨域媒体、伪元素、Web Component 都落到占位框，不留空洞。

库这头不如扩展的

  • 盖不了别人家的页面：重建第三方站点得先把 HTML 取回来，同源或本地转发口可以，公网站点多半被 CORS 挡住，取不到就只能原样显示。
  • 一次只管自己这一页：跨页常驻、随手换个网站再盖，是扩展才有的便利。
  • 它是进场动画：画面定格在采集那一瞬间，重建出来的盒子不带交互。
  • 上游改了表现，这里不会自动跟上——按公开行为重实现，不是 fork，也没有对方的排期。
  • 得发一次版才看得见：扩展装了就有，库要把这几个文件部署进站点。

怎么接

  1. 1

    装它

    零依赖，一个包三种格式；不想装也能直接引 CDN 上那个 IIFE。

    npm i swarm-builder
  2. 2

    指一个容器

    root 给谁就重建谁，页面其余部分照常跑；mount() 是最小写法。

    import { mount } from 'swarm-builder';

mount({
  root: document.querySelector('#app'),
  agentCount: 8,
  order: 'rows',   // 自上而下
  tour: true,      // 镜头跟着施工前沿
  sound: true,
});
  3. 3

    改到满意，再抄配置

    创造者模式挂在页面上，18 项参数一屏全露；调好一键导出，那份片段可以直接粘进代码。

    import { tune } from 'swarm-builder/tune';

tune({ root: '#app', initial: { order: 'depth', balance: true } });
给 AI 的提示词 把下面这段原样粘给 coding agent，它能在你自己的项目里接完 
用 swarm-builder 在我的项目里做「一群光标把页面重建出来」的进场动画。它是零依赖的 MIT 库，ESM / CJS / IIFE 三种格式都有。

1. 装：npm i swarm-builder；走 CDN 就引 dist/swarm-builder.iife.js，全局名 SwarmBuilder。框架里等容器挂载完再开局（React 用 useEffect、Vue 用 onMounted），部署就是把这几个文件当静态资源发出去，没有服务端。
2. 指一个容器来重建，页面其余部分不动：
   import { mount } from 'swarm-builder';
   mount({ root: document.querySelector('#app'), agentCount: 8, order: 'rows', tour: true, sound: true });
3. 要边看边调就换成创造者模式（右下角悬浮球，18 项日常参数一屏全露，另外 9 项「复刻参考实现」的开关折在同一块面板的一组里，改完点「应用并重跑」）：
   import { tune } from 'swarm-builder/tune';
   tune({ root: '#app', initial: { order: 'depth', balance: true } });
4. 常规参数：agentCount 1–24 个光标；order 取 group / rows / cols / snake / depth / radial / random；balance 按预估工时均衡各队列；speed 是 0.25–8 倍率，targetDuration 给秒数让估算器反推倍率；seed 固定即可重放（0 = 每局现抽）；maxItems 是蓝图上限，超出计入 dropped；ignore 用选择器跳过整棵子树；duplicate / maxCopies 管重复模块盖章；guides / maxGuides 管辅助线；grow 是标题字号步进；flocking 让光标互相避让；tour 让镜头跟随施工前沿；sound 是合成音效；theme 是施工线墨色；performanceMode 在密集页面自动裁剪特效。
5. 复刻参考实现的九个开关，默认全关、关着时行为与上面完全一致：flight（idle 停在落点 / live 待时绕圆心飞），pointer（ignore / follow 当圆心 / repel 48px 排斥环，只在 live 下有用），agents（fixed 固定 / auto 人数随滚动速度与积压活增减，上限 48），pick（queued 按预切队列 / live 每帧给所有活定价谁近谁抢），trigger（immediate 第一帧全放 / scroll 只放行滚过的部分，配 tour 用），adaptiveSpeed（积压每件 +45% 最多 4 倍），scan（single 走一遍 / pre-scroll 先把整页滚一遍等懒加载和图片，重建别人的站点要用这档），score（off 只有点击声 / generative 104 BPM 生成式配乐），reducedMotion（run 照跑 / skip 一项不建直接交还）。
6. 别做的事：不要为了动画改我的页面结构；这是进场动画，重建出来的盒子没有交互，结束后真实 DOM 原样交还。
7. 验收：跑完 console 无报错、文档宽度不超出视口、动画结束后原页面照常可交互。

参数速查

完整清单在 README；这里只挑最常动的几项，每一行都能在创造者模式里改。

参数取值它在管什么
agentCount1–24同时施工的光标数，越多越快，画面也越吵
ordergroup / rows / cols / snake / depth / radial / random光标怎么认领这一页；竖列在没有真沟时自动退回横带
balance布尔带按预估工时切等分而不是按件数，避免别人干等一个收尾
seed数字，0 = 现抽随机顺序的种子，完成状态会回显实际用的那颗
speed / targetDuration0.25–8 / 秒倍率，或交给估算器反推倍率把整场压进固定时长
tour布尔滚动跟着施工前沿走，结束交还页首
sound布尔合成音效，不用带音频文件
maxItems / ignore数字 / 选择器蓝图上限；命中的子树整块跳过
theme / performanceModeauto 优先施工线墨色按页面明暗；拥挤页面自动裁剪特效
flight / pointeridle·live / ignore·follow·repel干完活的光标停在落点，还是放回群蜂里绕着圆心转；绕的时候圆心是不是你的鼠标，要不要给鼠标配一圈 48px 的排斥环
agentsfixed·auto人数会不会变。auto 时你给的数是下限、48 是上限，滚动越快、可领的活越多招的人越多，闲了 2.5 秒的临时工自己离场
pick / triggerqueued·live / immediate·scroll守着切好的队列，还是每帧给所有活定价、谁近谁抢；整页第一帧全放行，还是只放行已经滚过的那部分
adaptiveSpeed布尔活堆起来就拧快时钟（积压每件 +45%，最多 4 倍）。开了以后 speed 与 targetDuration 变成下限而不是节奏
scansingle·pre-scroll采集是走一遍，还是先把整页滚一遍把懒加载和图片等出来，再回顶开始。重建别人的站点要用 pre-scroll
scoreoff·generative音效只是一串点击声，还是原版那套 104 BPM、按方块面积选八度的生成式配乐
reducedMotionrun·skip系统要求减少动效时照跑（宿主主动要的），还是一项不建、直接把真实页面交还

最后七行是「复刻参考实现」的开关：默认全部关着，关着的时候每帧算的东西、落下的像素都和原本一模一样——轨道场、动态班组、指针监听、运行时定价、配乐的混响只在打开时才构造。创造者模式面板把它们单独收在「参考实现复刻」一组，折叠着，一行一个 hover。想整页照着原版的做，就把它们一起打开再点「应用并重跑」。

用之前知道的几件事

  • 它是进场动画，不是懒加载：画面定格在采集那一瞬间，重建出来的盒子没有交互。
  • 页面很长先看 maxItems，超出的条目计入 dropped 而不是被盖出来。
  • 伪元素、跨域 canvas、Web Component 的 shadow DOM 会降级成占位框——有占位，不留空洞。
  • 浏览器要求页面已有用户手势才发声，所以自动开局的那一次可能静音，点一下就回来了。
  • 系统要求减少动效时怎么走由 reducedMotion 定：默认 'run' 照跑（这是宿主主动要的装饰），'skip' 则一项不建、直接把真实页面交还。
  • 预览壳里输入第三方地址，取得到 HTML 才会重建：同源页面与本地预览的同源转发可以，公网站点多半被 CORS 挡住，那就只原样显示。

效果基准来自 Chrome 扩展「Swarm Rebuild」，本项目按公开可观察的行为重新实现， 没有复制任何第三方源码。源码、Issue 与发行说明在 yancongya/swarm-builder ，MIT 许可。
